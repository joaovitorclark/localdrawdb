## 🔴 ALTO impacto

### A1. TableColumnList não está virtualizado de verdade
- **Arquivo:** `src/canvas/TableColumnList.tsx:216` (e `TableNode.tsx:191`)
- **Sintoma:** com 200 colunas, renderiza 200 `ColumnRowContent` + 4 Handles cada = 800 Handles por tabela. Em 100 tabelas, 80k Handles. Cada keystroke re-renderiza tudo (componente sem `memo`, props inline).
- **Por que importa:** scroll travando em tabelas largas é o gargalo #1 do app — você já confirmou isso em produção com `silver.fct_finance_wide` (200 colunas).
- **Esforço:** M (1-2 dias). Plano:
  1. Trocar `columns.map` por virtual list (ex.: `@tanstack/react-virtual`, ~10kb).
  2. `memo()` em `TableColumnList` + `ColumnRowContent` (deps estáveis).
  3. `memo()` em `TableNode` (quebra de re-render global).

### A2. Outline sem virtualização + split re-roda a cada tecla
- **Arquivo:** `src/editor/Outline.tsx:26-32`
- **Sintoma:** `splitDbmlBlocks(dbml)` parseia o DBML inteiro a cada keystroke; o resultado é renderizado como `<li>` plano, sem virtualização. Modelo de 500 blocos = 500 `<li>` re-renderizados a cada caractere digitado.
- **Por que importa:** usuário digitando no editor sente lag quando modelo cresce; outline fica inutilizável como ferramenta de navegação.
- **Esforço:** M (1-2 dias). Plano:
  1. `useDeferredValue(dbml)` + `useMemo` por nível (já existe em alguns lugares, replicar).
  2. Virtual list no painel.
  3. `memo()` nos items.

### A3. addTable / renameTable / renameColumn sem validação de duplicata
- **Arquivos:** `src/App.tsx:1316-1323` (addTable), `src/canvas/TableNode.tsx:72-74` (rename via prompt), `src/App.tsx:932-955` (onRenameColumn/onRenameTable)
- **Sintoma:** usuário cria `gold.dim_customer` e depois `Dim_Customer` (com casing diferente). `parseDbml` normaliza ambos para o mesmo `id`; render mostra duas tabelas ou uma só fica invisível; `focusTable` foca na errada.
- **Por que importa:** **corrompe o modelo silenciosamente**. Usuário perde trabalho sem aviso.
- **Esforço:** S (2-4h). Função `normalizeTableId(name)` em `dsl/parse.ts` (provavelmente já existe) + checar antes de adicionar/renomear. Mostrar erro inline no prompt (`window.prompt` está atrapalhando — idealmente trocar por modal).

### A4. `actions` no Context do App rebuilda todos TableNodes
- **Arquivo:** `src/App.tsx:940-955`
- **Sintoma:** `actions = useMemo(..., [selectColumn, layerOf, ...])` — `selectColumn` (getter do Zustand) e `layerOf` mudam referência em certas situações. Quando rebuilda, **todo TableNode re-renderiza** porque consome via Context.
- **Por que importa:** o `actions` é a fonte de handlers (rename, remove, color) para **todas** as tabelas do canvas. Um único rerender desse objeto cascateia em 100+ TableNodes.
- **Esforço:** S (2-4h). Dividir `actions` em 2 contexts: `actions` (estáveis, useCallback) e `readState` (que muda). Ou trocar Context por refs imperativas.

### A5. `opts` no Canvas rebuilda a cada render
- **Arquivo:** `src/canvas/Canvas.tsx:310`
- **Sintoma:** `opts` useMemo depende de `onToggleGroup` (handler do pai, sem `useCallback` no App). `opts` muda → `useCanvasNodes` effect re-dispara → `setNodes(...)` → todos TableNodes re-renderizam.
- **Por que importa:** toda interação no canvas que muda hover/seleção re-renderiza 100+ TableNodes só porque o `opts` mudou.
- **Esforço:** S (1-2h). `useCallback` em `onToggleGroup` no App.tsx; remover `onToggleGroup` das deps de `opts`.

### A6. `useCanvasNodes`/`useCanvasEdges` re-rodam a cada parse (keystroke)
- **Arquivos:** `src/canvas/hooks/useCanvasNodes.ts:138`, `src/canvas/hooks/useCanvasEdges.ts:343`
- **Sintoma:** deps dos effects incluem `parsed.tables` (identidade nova a cada keystroke), `selectedTableIds` (nova a cada seleção), `positions` (nova a cada drag). Efeito dispara `setNodes`/`setEdges` → reconciliação massiva.
- **Por que importa:** qualquer digitação no editor (mesmo em zona que não muda o modelo) re-renderiza o canvas inteiro.
- **Esforço:** M (meio dia). Chave estrutural com `JSON.stringify` dos campos que importam (positions, refs) em vez de identidade; separar "estrutura mudou" de "highlight mudou" em dois effects.

### A7. Ações destrutivas sem undo convincente
- **Arquivos:** `src/canvas/SelectionBar.tsx:48-60` (apagar selecionadas), `src/canvas/TableNode.tsx:105-109` (delete table via confirm)
- **Sintoma:** histórico do undo tem debounce 400ms (`App.tsx:346-361`) — ações dentro do debounce (incluindo múltiplos deletes rápidos) viram uma só baseline; undo desfaz "tudo" junto, não item por item.
- **Por que importa:** usuário perde trabalho se apagar várias tabelas por engano. Não há soft-delete nem "tem certeza?" específico.
- **Esforço:** M. Trocar debounce por commit-por-ação (history push por operação), ou adicionar modal de confirmação com lista do que será apagado.

## 🟡 MÉDIO impacto

### M1. Race `useDraggablePanel` + localStorage a cada mousemove
- **Arquivo:** `src/canvas/useDraggablePanel.ts:23-27`
- **Sintoma:** cada `mousemove` faz `setPos` (re-render do painel) **e** `localStorage.setItem(JSON.stringify(...))` síncrono.
- **Esforço:** S. Debounce do write (200ms) + `requestAnimationFrame` no `setPos` (1 render por frame).

### M2. `runSelected` engole erros async
- **Arquivo:** `src/palette/CommandPalette.tsx:43-48` e `:66-69`
- **Sintoma:** `void command.run()` — qualquer rejeição some. Se `focusColumn` explodir (ex.: tabela deletada entre Ctrl+K e Enter), palette fica aberta sem feedback.
- **Esforço:** S. try/catch + estado `error` + mostrar no rodapé da palette.

### M3. Rename de coluna via input: `onBlur` chama `onCommitEdit` mesmo após Esc
- **Arquivo:** `src/canvas/TableColumnList.tsx:80-89`
- **Sintoma:** usuário pressiona Esc (`onCancelEdit`) mas `onBlur` do input também dispara, e `onBlur` chama `onCommitEdit(oldName)` aplicando o rename parcial.
- **Esforço:** S. Flag `cancelledRef` por edição, ou setar timeout 0 entre Esc e onBlur.

### M4. switchProject pode perder trabalho se saveProject falhou
- **Arquivo:** `src/App.tsx:1202-1208`
- **Sintoma:** no `catch` do `load`, carrega SAMPLE sobrescrevendo dbml/positions locais sem aviso.
- **Esforço:** S. Mostrar erro (toast/modal) antes do fallback, com opção "manter local mesmo assim".

### M5. `useEffect` global de Cmd/Ctrl+S/K dependem de handlers não memoizados
- **Arquivo:** `src/App.tsx:648-679`
- **Sintoma:** deps incluem `undo`, `redo`, `handleSave`, `handleEditorCommit` — recriados a cada render → effect teardown + setup do listener a cada render.
- **Esforço:** S. Usar refs (`useEvent`) para o handler do listener, ou `useCallback` estável.

### M6. addLayer aceita nome vazio/duplicado; cores livres
- **Arquivo:** `src/canvas/LayersPanel.tsx:82-90`
- **Sintoma:** `prompt('Nome')` aceita `' '`, aceita nomes duplicados (toggle alterna um só). Cor hex livre aceita `'red'`/`'#xyz'`.
- **Esforço:** S. Validação + substituir `window.prompt` por input inline.

### M7. autolayout `resolveOverlaps` é O(n²) por iteração
- **Arquivo:** `src/canvas/autolayout.ts:400, 474`
- **Sintoma:** até 80 iterações × O(n²) — em 200 tabelas, ~2.5M comparações. Loop fica perceptível em modelos grandes.
- **Esforço:** M. Spatial index (grid hash) para reduzir overlap checks, ou AABB tree.

### M8. `structureKey` em useCanvasEdges faz `[object Object]` no join
- **Arquivo:** `src/canvas/hooks/useCanvasEdges.ts:328`
- **Sintoma:** `positions` é objeto, join força `'[object Object]'` — chave idêntica para qualquer positions → effect não re-roda quando deveria.
- **Esforço:** S. Substituir por `JSON.stringify` ou hash estável.

### M9. PageImportWizard / RenameConfirmModal sem focus trap nem scroll lock
- **Arquivos:** `src/editor/RenameConfirmModal.tsx:17-35`, `src/canvas/PageImportWizard.tsx`, `src/canvas/ProblemsPanel.tsx:68-112`
- **Sintoma:** Tab navega para elementos atrás do overlay; body continua scrollável; foco não retorna ao botão de origem ao fechar.
- **Esforço:** M. Hook `useFocusTrap` + hook `useBodyScrollLock` reutilizável.

### M10. SelectionBar esconde quando `selectedColumn` está setada
- **Arquivo:** `src/canvas/SelectionBar.tsx:18`
- **Sintoma:** `if (!selectedTableIds.length || selectedColumn) return null` — selecionar coluna esconde a barra que mostra as tabelas selecionadas. Usuário perde visibilidade.
- **Esforço:** S. Mostrar chips de tabela sempre, separadamente da info de coluna.

## 🏗️ Melhorias estruturais (long-term, alto esforço)

### E1. Memo/Context split
Dividir o Context de `actions` em 2: `actionsStable` (useCallback, nunca muda) e `readState` (Zustand selector). Reduz 80% dos re-renders em cadeia. **Pré-requisito para A4.**

### E2. Migrar para `@tanstack/react-virtual` em TableColumnList + Outline + LayersPanel
Resolve A1, A2 e parte de M10 num único PR. **Pré-requisito: ter TDD cobrindo seleção de coluna em tabela virtualizada.**

### E3. Debounce/coalesce do `parseDbml` em digitação rápida
Hoje roda síncrono a cada tecla. **Esforço:** S. `useDeferredValue` + worker (Comlink). Reduz travadas do editor em modelos grandes.

## Onde não mexer agora (false positives / YAGNI)

- **`App.tsx:280-337` dirty state no load**: cosmético, só pisca o ícone de não-salvo.
- **`Canvas.tsx:549-551` onNodeClick sem selectTable**: comportamento intencional (seleção de nó = via ReactFlow, store separado).
- **`Outline.tsx` state local sem persistência**: usuário não pediu pra persistir estado do outline entre sessões.
- **`palette/registry.ts:26-35` normalizeText recomputado**: irrelevante abaixo de 10k comandos.

## Próximo passo sugerido

Eu recomendo começar por **A3** (validação de duplicatas) + **A5** (memoizar onToggleGroup) + **A4** (estabilizar actions). São 3 itens de baixo esforço que juntos atacam o bug mais comum (perda de trabalho) e o gargalo de re-render global.

Depois, **A1 + A2 juntos** (virtualização) num PR único — é onde a percepção de performance vai melhorar mais visivelmente.
